# AgentLab MVP 产品功能说明

## 1. 产品概述

AgentLab Desktop 是一个基于 Electron、React 和 Claude Agent SDK 的本地 Agent 实验台。它面向需要理解、验证和调试编码 Agent 的开发者、技术负责人和 Agent 产品研发人员。

产品不是用普通聊天接口模拟工具调用，而是直接使用 Claude Agent SDK 运行 Agent Loop。模型负责理解目标和选择动作；SDK 负责工具执行、上下文、Session、权限、Hook、MCP 与 Subagent；AgentLab 负责桌面交互、配置、安全承载和事件观察。

当前版本为 MVP 0.1.0，设计参考 `Claude Code 产品与技术架构拆解.md`，借鉴的是“Agent 执行与治理系统”的产品和技术分层，不复制 Claude Code 的品牌、视觉资产或全部功能。

## 2. 产品价值

### 2.1 解决什么问题

普通模型对话主要交付文字建议，用户还要自行寻找文件、修改代码、执行命令和验证结果。AgentLab 将这些步骤串成一个受控闭环：

```text
提出目标 → 读取工作区 → 调用工具 → 权限判断 → 执行动作
        → 观察结果/错误 → 继续迭代 → 验证与总结 → 保存会话
```

它重点解决四类问题：

- 正确性：Agent 能读取真实项目、修改文件并运行验证，而不是只凭上下文猜测。
- 可控性：用户能限制工具、设置预算和轮次、审批高风险动作并随时停止。
- 连续性：聊天元数据和 SDK Session ID 被保存，后续可在同一上下文继续。
- 可观察性：用户能查看工具、权限、Hook、Thinking、成本、Token 与原始运行结果。

### 2.2 目标用户

| 用户                 | 典型目标                   | AgentLab 提供的价值                             |
| -------------------- | -------------------------- | ----------------------------------------------- |
| 应用开发者           | 理解、修改、调试代码       | 用自然语言驱动 Read/Edit/Bash 等真实工具        |
| Tech Lead / Reviewer | 审查正确性、安全与可维护性 | 使用只读工具、Reviewer Subagent 和完整事件证据  |
| Agent 产品研发       | 学习和调试 Agent Harness   | 调整模型、权限、Hook、MCP、结构化输出并观察差异 |
| 平台与安全人员       | 控制执行边界与成本         | 工具策略、Sandbox、预算、轮次、权限和凭据隔离   |

## 3. 产品架构与设计对应

参考文档将 Claude Code 概括为“System Prompt + Agent Loop + 工具运行时 + 权限治理 + 上下文工程 + 会话资产 + 扩展生态 + 多表面交互”。AgentLab MVP 对应实现如下：

| 参考设计能力 | AgentLab 当前实现                                                 |
| ------------ | ----------------------------------------------------------------- |
| 多表面交互   | Electron 桌面 Chat 与 Inspector                                   |
| Agent Loop   | Claude Agent SDK `query()`                                        |
| 工具运行时   | SDK 内置 Read、Glob、Grep、Edit、Write、Bash、Web、Agent 工具     |
| 权限治理     | `canUseTool`、六种权限模式、Allow/Deny、授权弹窗、Sandbox         |
| 上下文工程   | `claude_code` preset、追加/完整 System Prompt、设置来源、Thinking |
| 会话资产     | UI 会话 JSON、SDK Session ID、`resume`、SDK JSONL transcript      |
| 扩展生态     | MCP Server、Subagent、Plugin JSON 配置                            |
| 可观察性     | 流式文本、工具、权限、Hook、Result、成本、Usage、SDK诊断          |

关键边界是：Renderer 只负责 UI；Preload 提供固定 IPC；Electron Main 管理会话、凭据和 SDK 生命周期；工具真正由 SDK/Claude Code 子进程执行。AgentLab 不自行复制 Agent Loop 或工具执行器。

## 4. 快速开始

### 4.1 启动

```bash
npm install
export ANTHROPIC_API_KEY=sk-ant-...
npm run dev
```

要求 Node.js 20 或更高版本。Claude Agent SDK 已包含对应平台的 Claude Code 可执行文件，开发模式无需另装 Claude Code。

### 4.2 第一次完成任务

1. 点击左下角“配置 LLM API”，或在启动前设置环境变量。
2. 点击顶部文件夹按钮，选择希望 Agent 操作的工作区。
3. 保持默认权限模式；默认只自动允许 Read、Glob、Grep。
4. 输入：`请分析这个项目的入口、核心模块和数据流，不要修改文件。`
5. 在右侧“事件”查看读取、搜索、Thinking 和结果事件。
6. 再输入一个修改任务；在 Edit/Bash 请求出现时检查输入并选择允许或拒绝。

## 5. 功能说明

### 5.1 多会话 Agent Chat

**作用**

为每个任务提供独立的对话、工作区配置、状态、结果摘要和 SDK Session。支持新建、切换、删除和自动标题。

**使用场景**

- 同时探索不同仓库或不同问题。
- 将代码审查、Bug 修复、架构学习分成独立上下文。
- 重启桌面端后继续之前的任务。

**为什么需要**

Agent 任务包含大量工具结果和上下文。把不同目标混在一个会话里会增加模型干扰、成本和误操作风险，因此 Session 必须成为一等产品对象。

**如何使用**

- 点击左侧“新建实验”创建会话。
- 发送第一条消息后，会话标题自动取消息前 38 个字符。
- 点击左侧卡片切换会话；状态点显示空闲、运行、等待授权或错误。
- 点击垃圾桶删除 AgentLab 的会话记录。该操作不会删除 Claude SDK 自己保存的 JSONL transcript。

### 5.2 工作区选择

**作用**

指定 Agent 的默认工作目录，文件搜索、读取、编辑和命令都以它作为任务上下文。

**使用场景**

- 分析某个代码仓库。
- 只允许 Agent 在专用实验目录内工作。
- 为不同会话绑定不同工程上下文。

**为什么需要**

编码 Agent 必须知道“在哪个项目工作”。工作目录既影响结果正确性，也是文件访问和权限判断的重要安全边界。

**如何使用**

点击顶部工作区按钮或“运行配置 → 工作目录”，选择本地目录。新建会话默认继承当前会话的工作目录。

### 5.3 自然语言任务与流式回答

**作用**

用户用自然语言描述目标，Agent 可连续思考、调用多个工具、观察结果并最终回答。回答以 Markdown 展示并支持流式更新。

**使用场景**

- “分析这个项目的架构和数据流。”
- “修复这个测试失败并运行验证。”
- “审查当前代码中的安全风险。”

**为什么需要**

软件任务通常不是单轮问答，而是一个需要多次读取、执行和修正的循环。流式反馈让用户知道 Agent 正在工作，避免长任务成为黑盒。

**如何使用**

在底部输入任务，Enter 发送，Shift+Enter 换行。运行时发送按钮变为停止按钮。最终回答支持标题、列表、代码块和安全链接；脚本、事件属性和危险 URL 会被清理。

### 5.4 内置软件工程工具

**作用**

| 工具      | 作用                | 典型场景                         |
| --------- | ------------------- | -------------------------------- |
| Read      | 按需读取文件内容    | 理解实现、查看配置与错误日志     |
| Glob      | 按路径模式发现文件  | 找入口、测试、配置或同类文件     |
| Grep      | 搜索文本或代码特征  | 找符号、调用方、配置项和错误来源 |
| Edit      | 精确修改已有文件    | 修 Bug、重构、调整配置           |
| Write     | 新建或整体写入文件  | 创建模块、测试或文档             |
| Bash      | 执行系统命令        | 运行测试、构建、Git 和诊断命令   |
| WebSearch | 搜索外部最新信息    | 查询官方文档、版本和兼容性信息   |
| WebFetch  | 读取网页内容        | 获取指定文档或页面证据           |
| Agent     | 调用自定义 Subagent | 隔离审查、探索或专项分析         |

**为什么需要**

模型无法把整个仓库一次放入上下文，也不能仅靠文字建议验证软件结果。搜索、读取、修改和真实命令执行共同构成“证据驱动的完成闭环”。

**如何使用**

在“运行配置 → 工具”中对每个工具分别设置：

- 启用：是否把工具提供给模型。
- 自动允许：匹配时跳过人工确认，不等于工具白名单。
- 禁止：明确阻止工具使用。

默认启用全部九种工具，但只自动允许 Read、Glob、Grep。

### 5.5 权限模式与原生授权弹窗

**作用**

在真实文件、命令和网络动作执行前进行策略判断，并将需要用户决定的操作回传桌面端。

**使用场景**

- 允许 Agent 读取代码，但逐次确认编辑和命令。
- 评审场景只允许分析，不允许修改。
- 在可信、可丢弃的环境中降低确认频率。

**为什么需要**

编码 Agent 能改变文件、运行任意命令和访问外部系统。权限不是视觉提示，而是工具数据流中的执行闸门。

**如何使用**

在“运行配置 → 运行 → 权限模式”中选择：

| 模式                | 用途                                              |
| ------------------- | ------------------------------------------------- |
| `default`           | 默认安全体验，需要时询问用户                      |
| `acceptEdits`       | 自动接受符合 SDK 策略的编辑，其他高风险动作仍受控 |
| `plan`              | 只调研和规划，适合复杂或高风险任务前对齐方案      |
| `dontAsk`           | 不弹出交互询问，不能自动批准的动作会被拒绝        |
| `auto`              | 使用 SDK 自动权限策略                             |
| `bypassPermissions` | 跳过全部权限检查，仅限完全可信的隔离环境          |

授权弹窗会显示工具名、描述、受影响路径和完整输入。用户可以“拒绝”“仅允许一次”；当 SDK 提供可持久化权限建议时，还可以选择“本会话始终允许”。

### 5.6 任务停止

**作用**

立即释放输入区，同时要求 SDK 中断当前 Query，并清理等待中的权限请求。

**使用场景**

- Agent 方向错误或消耗过高。
- 命令运行时间过长。
- 权限弹窗出现后决定取消整个任务。

**为什么需要**

Agent 是长链路过程；如果只能等待自然结束，用户无法控制成本、风险和时间。停止还必须防止旧运行的迟到事件污染下一次任务。

**如何使用**

任务运行或等待授权时点击输入区右下角的方形停止按钮。状态会恢复为就绪，并在会话中记录任务被用户停止。

### 5.7 模型与执行强度

**作用**

按会话选择主模型、Fallback 模型、Effort 和 Thinking 策略。

**使用场景**

- 简单检索使用较低 Effort，降低延迟和成本。
- 复杂架构或调试任务提高 Effort。
- 主模型不可用时自动切换 Fallback。
- 比较 adaptive、固定预算和关闭 Thinking 的效果。

**为什么需要**

不同任务对推理深度、速度、成本和稳定性的要求不同，统一固定配置无法兼顾日常使用与实验对比。

**如何使用**

在“运行配置 → 运行”设置：

- 模型留空时使用 SDK 默认模型。
- Fallback 可选。
- Effort 支持 low、medium、high、xhigh、max。
- Thinking 支持 adaptive、fixed budget、disabled；固定预算时填写 token 数。

### 5.8 Turns、预算、Sandbox 与 Checkpoint

**作用**

为长任务设置硬边界，并启用 SDK 的沙箱和文件历史能力。

**使用场景**

- 防止 Agent 因反复失败而无限迭代。
- 给实验设置美元成本上限。
- 限制 Bash 和文件访问风险。
- 为未来的文件回退保留 SDK checkpoint。

**为什么需要**

Agent Loop 的价值来自持续执行，但持续执行也带来失控和成本风险。产品必须同时提供时间、轮次、预算和执行环境边界。

**如何使用**

在“运行配置 → 运行 → 边界”设置最大 Turns 和预算（USD），并开关 Sandbox、文件 Checkpoint。当前 UI 尚未提供 `rewindFiles()`，Checkpoint 仅为 SDK 层能力准备。

### 5.9 额外工作目录

**作用**

将工作区外的指定绝对路径加入 SDK 可访问范围。

**使用场景**

- 主仓库需要读取相邻共享库。
- 任务需要对照外部配置或生成目录。
- Monorepo 之外存在受控依赖源码。

**为什么需要**

只允许单一工作目录可能无法覆盖真实工程，而无限扩大文件范围又不安全，因此需要显式、逐目录授权。

**如何使用**

在“运行配置 → 工具 → 额外目录”中每行填写一个绝对路径。只添加任务必需的目录。

### 5.10 实时事件观察器

**作用**

展示归一化后的 Agent 运行事件，包括文本流、Thinking、工具调用、工具结果、权限、Hook、System、Result、建议和错误。

**使用场景**

- 判断 Agent 为什么选择某个工具。
- 排查权限、MCP、模型或工具失败。
- 对比不同模型、Prompt 和配置的运行路径。
- 获取成本、轮次、Token 和停止原因。

**为什么需要**

Agent 是带状态的事件循环，只看最终回答无法判断它是否真正读取、修改和验证。事件记录是调试、审计和产品实验的基础。

**如何使用**

点击右侧“事件”标签。事件按时间倒序展示，可展开查看输入/结果 JSON。对话区底部还会显示最近四条工具、权限或 Hook 事件。

### 5.11 Hook 观察

**作用**

观察 PreToolUse、PostToolUse、PostToolUseFailure、SubagentStart、SubagentStop、PreCompact、PostCompact 和 Stop 生命周期事件。

**使用场景**

- 调试工具执行顺序和失败位置。
- 验证子 Agent 生命周期。
- 为未来审计、策略或自动化 Hook 设计事件模型。

**为什么需要**

扩展和企业流程不能全部硬编码进 Agent Loop。Hook 提供生命周期切入点，也让宿主能够观察执行过程。

**如何使用**

在“运行配置 → 运行 → 可观察性”打开“Hook 事件”，执行包含工具调用的任务，然后在事件页查看。当前 MVP 将 Hook 用于观察，不提供可视化 Hook 脚本编辑器。

### 5.12 SDK 诊断与运行摘要

**作用**

显示 Agent SDK、Claude Code Session、Electron、Node.js、平台架构和事件数量；Result 记录耗时、API耗时、轮次、成本、停止原因、Usage 和权限拒绝。

**使用场景**

- 报告问题时提供环境信息。
- 判断失败来自宿主、SDK、模型还是权限。
- 比较实验成本与性能。

**为什么需要**

Agent 调用链长、依赖多，只有最终错误通常不足以定位问题。环境和运行摘要可显著降低复现成本。

**如何使用**

打开右侧“SDK”标签查看诊断；点击“打开 AgentLab 数据目录”查看本地状态文件；在事件页展开 Result 查看单次运行指标。

### 5.13 下一步 Prompt 建议

**作用**

接收 SDK 返回的下一步建议，并显示为输入框上方的快捷操作。

**使用场景**

- 完成代码分析后继续实施。
- 修复后继续运行测试或审查。
- 帮助不熟悉 Agent 工作流的用户推进任务。

**为什么需要**

复杂任务往往分多轮完成。建议能够减少用户重新组织 Prompt 的成本，并形成连续工作流。

**如何使用**

在可观察性配置中打开“下一步提示建议”。当 SDK返回建议时，点击建议条将内容放入输入框，也可点击关闭图标忽略。

### 5.14 System Prompt 与 Claude Code Preset

**作用**

控制 Agent 的基础角色、工作原则和回答要求。可以在 Claude Code 编码 Agent preset 上追加指令，也可以完全替换 System Prompt。

**使用场景**

- 规定先验证再修改。
- 创建只读审计或特定编码规范实验。
- 对比通用模型 Prompt 与完整编码 Agent preset。

**为什么需要**

模型能力必须被明确产品规则约束。System Prompt 决定工具使用方式、行为边界和交付质量，是上下文工程的核心组成。

**如何使用**

在“运行配置 → 提示词”中：

- 开启 preset：输入内容作为追加指令，保留完整编码 Agent 行为。
- 关闭 preset：输入内容成为完整 System Prompt。

### 5.15 文件设置来源

**作用**

决定 SDK 是否加载 user、project、local 三层配置和项目指令。

**使用场景**

- 使用团队仓库中的 `CLAUDE.md` 和 `.claude/settings.json`。
- 加载个人通用设置。
- 使用不提交 Git 的本地覆盖配置。
- 做隔离实验时关闭特定来源。

**为什么需要**

编码 Agent 的上下文不只是聊天历史，还包括用户习惯、团队规则和本地覆盖。显式设置来源可以平衡一致性、个性化与实验可重复性。

**如何使用**

在“运行配置 → 提示词 → 文件设置来源”勾选：

- user：`~/.claude/settings.json`
- project：`.claude/settings.json` 与 `CLAUDE.md`
- local：`.claude/settings.local.json`

默认启用 project 和 local。

### 5.16 JSON Schema 结构化输出

**作用**

使用 JSON Schema 约束 Agent 最终结果，让输出能够被程序稳定解析和校验。

**使用场景**

- 生成标准代码审查结果。
- 输出自动化测试报告或风险列表。
- 将 AgentLab 结果交给后续系统处理。

**为什么需要**

自由文本适合人阅读，但自动化系统不能依赖脆弱的文本解析。Schema 将结果格式变成显式契约。

**如何使用**

在“运行配置 → 提示词 → 结构化输出”填写合法 JSON Schema。编辑器显示“有效 JSON”后发送任务；留空则恢复普通文本。JSON 语法有效不代表 Schema 语义一定有效，后者由 SDK/模型运行时反馈。

### 5.17 MCP Server 配置

**作用**

将外部工具和资源通过 Model Context Protocol 接入 Agent。

**使用场景**

- 连接内部知识库、数据库或研发平台。
- 使用团队自建工具而不修改 AgentLab 核心。
- 验证 stdio 或其他 SDK 支持的 MCP Server。

**为什么需要**

任何产品都不可能内置全部企业工具。MCP 用统一协议扩展 Agent 能力，避免每种系统都侵入主循环。

**如何使用**

在“运行配置 → 扩展 → MCP Servers”填写 `Record<string, McpServerConfig>` JSON。需要所有配置严格有效时打开“严格 MCP 配置”。只接入可信服务并检查它们暴露的工具权限。

### 5.18 自定义 Subagent

**作用**

定义具备独立说明、工具、模型和最大轮次的专业 Agent，由主 Agent 通过 Agent 工具调用。

**使用场景**

- 让 reviewer 只读审查代码。
- 将专项探索隔离出主上下文。
- 对不同角色配置不同工具和成本边界。

**为什么需要**

大任务全部放在主上下文会增加污染和成本。Subagent 能实现角色分工、上下文隔离和更细的工具约束。

**如何使用**

在“运行配置 → 扩展 → Subagents”编辑 `Record<string, AgentDefinition>`。默认提供 reviewer 示例，只允许 Read、Glob、Grep，继承主模型，最大 12 Turns。确保内置 Agent 工具已启用，然后在 Prompt 中明确要求调用该 Subagent。

### 5.19 本地 Plugin 配置

**作用**

将 SDK 支持的本地 Plugin 配置传入运行时，用组合包扩展 Agent 能力。

**使用场景**

- 试验团队自定义插件。
- 组合 Hooks、Agents、MCP 或其他 SDK 扩展。
- 验证插件与主 Agent 的兼容性。

**为什么需要**

扩展能力需要可分发、可组合的载体，不能要求每次都修改宿主代码。

**如何使用**

在“运行配置 → 扩展 → 本地 Plugins”填写 `SdkPluginConfig[]` JSON。当前 MVP 是实验编辑器，没有插件市场、安装器、版本管理或可信度审核。

### 5.20 LLM Provider 与加密凭据

**作用**

支持 Anthropic API、Anthropic 兼容网关和启动环境变量三种连接方式，并安全保存应用内凭据。

**使用场景**

- 直接使用 Anthropic API。
- 使用企业代理或兼容网关。
- 由 Shell、CI 或企业环境统一注入认证信息。

**为什么需要**

Agent 无法脱离模型服务运行，但 API Key 是高敏感信息。桌面端必须提供易用配置，同时阻止 Key 进入 Renderer、会话 JSON、Git、Bash、Hooks 或 stdio MCP 子进程。

**如何使用**

点击左下角“配置 LLM API”或 SDK 面板中的同名按钮：

1. 选择 Provider。
2. 兼容网关填写 HTTP(S) Base URL。
3. 选择 X-Api-Key 或 Bearer Token。
4. 可设置默认模型并输入 Key。
5. 点击“安全保存”。

应用使用 Electron `safeStorage`/macOS Keychain 加密整体配置，UI只显示 Key 尾四位。若系统安全存储不可用，应用拒绝保存。运行时启用子进程环境清理，降低工具和扩展读取模型凭据的风险。

### 5.21 本地会话持久化与 SDK Resume

**作用**

AgentLab 原子保存轻量 UI 会话；Claude SDK 保存完整 JSONL transcript；两者通过 `sdkSessionId` 关联。

**使用场景**

- 关闭并重启桌面端后恢复聊天列表。
- 在同一会话继续追问，保留之前的模型上下文。
- 分离 UI 元数据和 SDK 的完整执行记录。

**为什么需要**

长任务跨越多轮甚至多个工作时段。没有持久化与 Resume，每次重启都要重新建立上下文，也无法形成可审计的会话资产。

**如何使用**

无需额外操作。创建会话、更新配置和收发消息时会自动写入 `agentlab-state.json`；SDK返回 Session ID 后，下一次运行自动传入 `resume`。状态文件损坏时会被保留为 `.corrupt-<timestamp>`，应用以新状态恢复启动。

## 6. 推荐使用方式

### 6.1 安全理解项目

1. 选择仓库。
2. 使用 `plan` 或 `default` 模式。
3. 只启用/自动允许 Read、Glob、Grep。
4. Prompt：`分析项目入口、模块边界和核心数据流，引用具体文件，不修改任何内容。`
5. 在事件页确认 Agent 实际读取了相关证据。

### 6.2 修复并验证 Bug

1. 使用 `default` 模式，启用 Read、Grep、Edit、Bash。
2. Prompt 中提供现象、复现方式和预期。
3. 检查每个 Edit/Bash 权限请求。
4. 要求 Agent 修改后运行定向测试和构建。
5. 在 Result 中检查轮次、成本和停止原因，并人工查看 Git diff。

### 6.3 只读代码审查

1. 使用默认 reviewer Subagent，或只启用 Read、Glob、Grep、Agent。
2. 禁止 Edit、Write、Bash。
3. Prompt：`调用 reviewer 审查当前工作区，按严重程度列出有文件证据的正确性、安全和可维护性问题。`
4. 查看 Subagent 与工具事件，确认没有修改动作。

### 6.4 自动化格式实验

1. 设置较低最大 Turns 和预算。
2. 填写 JSON Schema。
3. 使用固定测试仓库和固定 Prompt。
4. 调整模型、Effort 或 System Prompt，多次执行并比较 Result、成本和 Schema 合规性。

## 7. 安全使用原则

- 优先在 Git 仓库或可恢复的临时目录中运行。
- 默认只自动允许只读工具，逐次检查 Edit、Write 和 Bash。
- 不在包含生产凭据、个人数据或线上访问令牌的目录测试。
- `bypassPermissions` 只用于完全可信、隔离且可丢弃的环境。
- MCP 和 Plugin 拥有各自的执行能力，接入前应单独审查来源与权限。
- Sandbox 是纵深防御配置，不应替代操作系统隔离、最小权限和人工审批。
- 最终回答不等同于验证证据；重要变更仍应检查 Git diff、测试输出和构建结果。

## 9. 数据与文件

| 数据           | 位置/管理者                                 | 内容                                       |
| -------------- | ------------------------------------------- | ------------------------------------------ |
| UI 会话状态    | Electron userData 下 `agentlab-state.json`  | 会话、消息、配置、SDK Session ID、最后结果 |
| LLM 凭据       | Electron userData 下 `llm-credentials.json` | 系统安全存储加密后的整体配置，不含明文 Key |
| SDK transcript | Claude Agent SDK 管理                       | 完整 JSONL 会话与工具上下文                |
| 工作区文件     | 用户选择的目录                              | 由 SDK 工具在权限规则下读取或修改          |

可以在右侧“SDK”面板点击“打开 AgentLab 数据目录”定位前两类文件。

## 10. MVP 验收判断

当用户能在受控工作区中完成以下流程时，可认为核心产品闭环成立：

1. 安全配置模型并创建会话。
2. Agent 使用只读工具建立项目证据。
3. 用户检查并批准一次文件修改或命令执行。
4. Agent 根据工具结果继续迭代并完成验证。
5. 用户在事件页看到工具、权限、Hook、成本和结果。
6. 重启应用后，同一会话能够继续追问。
7. 用户能够拒绝危险动作或停止正在运行的任务。

详细验收步骤与预期结果见 `docs/AgentLab-MVP-测试方案.md`。
